> **At a glance:** We evaluated 57 held-out sentence records for participant S5. Five supplied checkpoint-prediction files were combined with a weighted ensemble, then rescored using a Spanish character-level 9-gram KenLM model. CER improved from **42.0490% to 38.0195%**, and WER improved from **77.4123% to 69.2836%**.

---

## 1. Project overview

[Brain2Qwerty](https://github.com/facebookresearch/brain2qwerty) is a research system for decoding sentences typed by participants from non-invasive brain recordings. The V1 system predicts keystroke-related character sequences from brain activity. Its official implementation describes a convolutional encoder followed by a sentence-level Transformer, with optional character n-gram language-model beam-search decoding.

This repository documents **Track B: checkpoint-based reproduction**. Instead of training the neural network again, this run starts from prediction CSVs already generated by supplied checkpoint branches. We combine those predictions and apply the language-model decoding stage.

### What this project includes

- One-subject evaluation: **S5 only**.
- 57 aligned held-out sentence records.
- Five frozen checkpoint-prediction inputs.
- A fixed weighted ensemble.
- Spanish character-level 9-gram KenLM decoding.
- Raw-versus-decoded CER and WER evaluation.
- Saved prediction CSVs and aggregate summaries.

### What this project does not claim

- It does not train Brain2Qwerty V1 from scratch.
- It does not run fresh neural-network inference on raw EEG/MEG recordings.
- It does not reproduce all 19 MEG participants.
- It is not a complete reproduction of every experiment in the Nature Neuroscience paper.

## 2. Dataset and input files

### 2.1 Dataset background

The Brain2Qwerty V1 work uses the **SpanishBCBL** dataset, collected by the Basque Center on Cognition, Brain and Language (BCBL). The official project points to the dataset on Hugging Face:

- Dataset: [BCBL SpanishBCBL](https://huggingface.co/datasets/bcbl190626/SpanishBCBL)
- Official implementation: [facebookresearch/brain2qwerty](https://github.com/facebookresearch/brain2qwerty)
- V1 implementation notes: [Brain2Qwerty V1 README](https://github.com/facebookresearch/brain2qwerty/tree/main/brain2qwerty_v1)

The full research dataset contains brain recordings and associated behavioural information. The official V1 documentation describes MEG recordings, EEG recordings, and behavioural .mat files. The complete dataset is large (approximately 262 GB according to the V1 documentation).

**Important distinction for this reproduction:** we did not download or process the raw SpanishBCBL recordings in this Track B run. We used supplied, already-generated held-out prediction CSVs for S5. Therefore, the 57 rows in our evaluation are sentence-level prediction records, not 57 raw EEG/MEG recordings.

### 2.2 The five prediction files used

All five files were supplied as inputs to the ensemble workflow:

| Input file | Short name | Role in this run |
|:--|:--|:--|
| gate005_full_test.csv | gate005 | Main gated prediction branch |
| late_soup_test.csv | late | Late-soup prediction branch |
| seed101_e10_test.csv | seed101 | Seed 101 prediction branch |
| seed202_e26_test.csv | seed202 | Seed 202 prediction branch |
| l2reg_seed404_e6_test.csv | l2e6 | L2-regularised seed 404 prediction branch |

Each input contained **57 S5 test records**. Before combining them, we checked that the sentence records aligned across all five files. This alignment check is important: predictions must refer to the same sentence in every branch before their logits can be combined.

The frozen prediction inputs are part of the upstream [Brain2Qwerty V1 beta release](https://huggingface.co/farmakohealth/brain2qwerty-v1-beta). The raw SpanishBCBL recordings themselves are not included in that beta prediction bundle.

### 2.3 Language-model file

The decoding stage used the supplied Spanish character-level 9-gram KenLM model.

- Model type: character-level n-gram language model
- Language: Spanish
- Order: 9-gram
- Purpose: score candidate character sequences and help beam search prefer more plausible Spanish text

The language model is a post-processing component. It does not replace the checkpoint predictions; the decoding step uses it to rescore candidate text hypotheses.

## 3. Methodology: what we did

The complete S5 workflow was:

1. **Select the S5 test records** from each of the five frozen prediction CSVs.
2. **Check alignment** using the sentence identifiers. Each file had 57 rows, and the sentence UIDs matched across all five inputs.
3. **Combine the five branches** with the fixed weighted ensemble described below.
4. **Prepare and load KenLM.** The environment was configured with Python 3.12 and a KenLM build capable of loading the supplied 9-gram model. We verified that the model loaded successfully and reported order 9.
5. **Run a one-record pilot** to verify that the decoder and language model worked before running the full S5 set.
6. **Decode all 57 records** using beam search and the selected decoder settings.
7. **Evaluate both outputs** against the reference sentences, calculating raw and language-model CER/WER.
8. **Save the outputs** and aggregate summaries in results/S5/.

### 3.1 Weighted ensemble

We used the following fixed recipe:

~~~python
weights = {
    "gate005": 0.675,
    "late":     0.100,
    "seed101":  0.100,
    "seed202":  0.100,
    "l2e6":     0.025,
}
~~~

The weights sum to 1.0. The main gate branch contributes 67.5% of the ensemble, while the other four branches contribute the remaining 32.5%.

Conceptually, the ensemble combines the aligned model outputs using these weights:

~~~python
# Illustrative pseudocode for the weighted combination.
# The actual workflow reads the logits from the five prediction files.

ensemble_logits = (
    0.675 * gate005_logits
    + 0.100 * late_logits
    + 0.100 * seed101_logits
    + 0.100 * seed202_logits
    + 0.025 * l2e6_logits
)
~~~

The resulting ensemble predictions are the **raw ensemble** output, before KenLM decoding.

### 3.2 KenLM decoding configuration

| Parameter | Value |
|:--|--:|
| Language model | Spanish character-level 9-gram KenLM |
| Beam size | 200 |
| Maximum labels | 10 |
| LM weight | 2.05 |
| Space bias | 0.0 |
| Repeat penalty | -0.05 |
| Acoustic weight | 1.0 |
| Logit temperature | 1.0 |
| Workers | 4 for the full run |

The language model searches candidate character sequences and uses its learned character n-gram probabilities to rescore them. The purpose is to improve the linguistic plausibility of the decoded sentence while retaining evidence from the ensemble predictions.

### 3.3 Metric calculation

We evaluated the raw ensemble text and the final KenLM text against the reference sentence for each record.

- **Character Error Rate (CER):** character-level edit distance divided by the number of reference characters.
- **Word Error Rate (WER):** word-level edit distance divided by the number of reference words.

~~~python
CER = total_character_edits / total_reference_characters
WER = total_word_edits / total_reference_words
~~~

The aggregate metrics were independently recomputed from the 57 output records and checked against the decoder summary.

## 4. Results

| Metric | Before KenLM | After KenLM | Absolute improvement |
|:--|--:|--:|--:|
| **CER ↓** | 42.0490% | **38.0195%** | **4.0295 percentage points** |
| **WER ↓** | 77.4123% | **69.2836%** | **8.1287 percentage points** |

Relative error reduction:
- CER: approximately **9.59%**
- WER: approximately **10.50%**

### What these results mean

- Both CER and WER decreased after language-model decoding. This indicates that KenLM improved aggregate transcription accuracy for this S5 run.
- CER improved by about 4.03 percentage points.
- WER improved by about 8.13 percentage points.
- The final CER is approximately 38.02%, while the final WER is approximately 69.28%.
- WER remains higher than CER, meaning word-level errors are still substantial even after decoding.

Lower CER and WER values indicate better performance.

## 5. Comparison with the original Brain2Qwerty V1 paper

The original study is:

**Lévy, J., Zhang, M., Pinet, S. et al. (2026).** *Noninvasive decoding of typed sentences from human brain activity.* Nature Neuroscience, 29, 2438–2444. [https://doi.org/10.1038/s41593-026-02303-2](https://doi.org/10.1038/s41593-026-02303-2)

The paper reports a mean MEG CER of approximately **29%** across its MEG cohort. Its participant-level results show a median MEG participant CER of approximately **38%**. The V1 beta release also provides a broader held-out reference summary across 19 subjects.

| Result | Scope | CER | WER |
|:--|:--|--:|--:|
| Original paper — MEG mean | Cohort mean across 19 MEG participants | **~29.0%** | Not reported as a headline value |
| Original paper — median participant | Median MEG participant (paper figure) | **~38.0%** | Not reported |
| V1 beta release reference | 19 subjects / 521 held-out records | **29.0964%** | **56.0564%** |
| **Our reproduction — S5** | **1 subject / 57 records, after KenLM** | **38.0195%** | **69.2836%** |

### Interpretation

1. **Compared with the paper's cohort mean:** our S5 CER (38.0195%) is about 9.02 percentage points higher than the reported mean MEG CER (~29%). This is a difficult comparison because our result is for one subject, whereas the paper value is an average across participants.
2. **Compared with the paper's median participant:** our S5 CER is numerically very close to the paper's approximate median participant CER (~38%). This is a contextual observation only; it does not establish that S5 corresponds to the paper's median participant.
3. **Compared with the 19-subject beta reference:** our S5 CER and WER are higher than the 19-subject aggregate values. A single participant's score should not be expected to equal a multi-participant aggregate.
4. **WER comparison:** the paper's headline result is generally reported in CER, so we do not claim a direct paper-versus-S5 WER comparison.

### Why this is not an exact apples-to-apples comparison

- Our run covers one subject (S5), not the complete 19-subject cohort.
- We start from supplied frozen prediction CSVs rather than training and evaluating the full neural network ourselves.
- The paper's cohort mean, its median participant, and the beta bundle's 19-subject summary are different aggregation scopes.
- The beta bundle's decoder recipe and evaluation context should not be treated as identical to every result reported in the paper.

**Overall conclusion:** The S5 checkpoint-based pipeline successfully produced a measurable improvement after KenLM decoding. Its final CER is close to the paper's reported median participant value, but the run remains a single-subject checkpoint-based reproduction—not a full reproduction of the original paper.

## 7. Reproducibility notes and limitations

- **Subject scope:** S5 only. No other subject was included in this run.
- **Record count:** 57 aligned sentence records.
- **Prediction provenance:** supplied frozen prediction branches from the V1 beta bundle.
- **Language model:** supplied Spanish character-level 9-gram KenLM model.
- **Neural model training:** not performed in this Track B run.
- **Raw recording processing:** not performed in this Track B run.
- **Metric validation:** aggregate values were independently recomputed from the saved S5 predictions.
- **Environment note:** KenLM was configured in a Python 3.12 environment and its 9-gram model load was verified before decoding.
